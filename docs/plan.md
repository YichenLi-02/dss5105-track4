# Delivery plan

This is a proposed team plan, not additional course requirements.

| Workstream | Owner | Status | Acceptance criteria |
| --- | --- | --- | --- |
| Problem definition and architecture | TBD | planned | One target workflow, architecture and assumptions documented |
| Message ingestion | TBD | planned | Synthetic fixture loads; integration feasibility documented |
| Triage and deadline extraction | TBD | planned | Outputs retain source evidence and handle ambiguous dates |
| Weekly planning | TBD | planned | Conflicts and infeasible tasks are surfaced |
| User interface | TBD | planned | Student can inspect, correct and approve suggestions |
| Evaluation | TBD | planned | Held-out protocol, manual baseline and category results |
| Documentation and demo | TBD | planned | Clean-checkout instructions and required deliverables verified |

## Sprint 1

Define the problem and business value, create the architecture diagram, identify risks and assumptions, and present the Sprint 2 roadmap with success criteria. Prototype one synthetic message-to-task flow.

## Sprint 2

Demonstrate an end-to-end interface. Report implemented/planned features with owners and statuses. Declare the validation plan, freeze the held-out set, and prepare the video and slides.

## Sprint 3

Complete evaluation, analyse at least 10 individual failure cases, document limitations, rehearse the demo, verify public repository/demo links, and prepare final deliverables.

## Initial issues to create

- Define target student workflow and success criteria.
- Validate Outlook / Teams access feasibility and synthetic-data fallback.
- Design message/task schema with source references and time zones.
- Implement the first message-to-task vertical slice.
- Design weekly planning and review interface.
- Build development and held-out evaluation sets.
- Run manual baseline and report quality/time results.
- Prepare documentation, contribution records and demo.
