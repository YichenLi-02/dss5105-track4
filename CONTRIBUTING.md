# Team workflow

1. Create an issue describing the task, owner, sprint and acceptance criteria.
2. Branch from `main`: `feat/short-description`, `fix/short-description`, or `docs/short-description`.
3. Keep changes focused and use meaningful commit messages.
4. Open a pull request linking the issue; describe behaviour, verification and limitations.
5. Ask another team member to review before merging. This is a team convention, not an enforced repository rule yet.
6. Update documentation and the ownership/status table when work changes.

Record actual contributions throughout the project for Teams.pdf. Never invent contribution percentages or evaluation results.
